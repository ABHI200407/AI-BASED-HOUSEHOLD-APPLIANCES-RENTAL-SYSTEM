# RentAI: Dataset-Grounded Simulation, Provenance & AI Model Documentation

## 1. Executive Summary & Defensible Architecture

RentAI has been transitioned from a static frontend prototype into a **real-world data-grounded ecosystem simulation**. The system integrates:
1. **Immutable Source Layer (Layer 1)**: Raw dataset records from real-world Kaggle repositories.
2. **Normalized Application Layer (Layer 2)**: Canonical `User`, `Appliance`, and `Inventory` entities derived directly from source records.
3. **Behavioral Simulation Layer (Layer 3)**: An event-driven state machine advancing on a virtual simulation clock (`SimulationClock`) calibrated on empirical distributions.
4. **Machine Learning Engines**:
   - **Recommendation System**: Collaborative filtering with explainable scoring factors and rationale.
   - **Churn Prediction Engine**: Random Forest RFM classifier outputting risk probabilities, risk levels, and ranked feature impacts.
5. **Full Provenance Tracing**: Every record in the database carries explicit provenance identifying whether it is `SOURCE`, `APPLICATION`, `SIMULATION`, or `MODEL`.

## 2. Real-World Datasets Utilized

| Dataset Name | Source Repository | Records Ingested | Primary Fields Extracted | Operational Role in RentAI |
|---|---|---|---|---|
| **Rental Churn Dataset** | Kaggle (`rental_churn_dataset.csv`) | 1,500 records | `customer_id`, `tenure_months`, `monthly_spend`, `active_rentals`, `late_payments`, `early_returns`, `cart_abandonment`, `days_inactive`, `avg_rating`, `churn` | Populates Layer 1 `SourceCustomer` and projects into verified Layer 2 `User` (tenants). Calibrates tenant behavior and churn risk. |
| **Personalized Recommendation Dataset** | Kaggle (`personalized_recommendation_dataset.csv`) | 150,000 interactions | `User_ID`, `Item_ID`, `Category`, `Rating`, `Timestamp`, `Price`, `Platform`, `Location` | Ingests into Layer 1 `SourceInteraction`. Powers collaborative matrix factorization and empirical category preference distributions. |
| **Retail Store Inventory & Demand Dataset** | Kaggle (`demand_data.csv` & `sales_data.csv`) | 1,825 daily points / 76,000 records | `date`, `category`, `active_rentals`, `Demand`, `Price`, `Inventory Level` | Feeds the 30-Day Demand Forecasting BI Dashboard with actual category rental series across AC, Refrigerator, Washing Machine, Microwave, and TV. |

### Dataset Limitations & Ethical Transparency
1. **Cross-Dataset Join Isolation**: Customers from the churn dataset are never artificially conflated with users from the recommendation dataset without explicit join keys.
2. **Rental Lifecycle Realism**: Real e-commerce datasets capture purchases and views rather than physical rental handovers. Rental handovers, technician dispatch, maintenance, and deposit refunds are explicitly recorded as `data_origin: "simulation"` to maintain academic integrity.

## 3. The Three Data Layers & Provenance Specification

Every record in the MongoDB database is tagged with strict provenance attributes:

```json
{
  "entity_type": "Booking",
  "entity_id": "6ab7b2959442094b4d2c2589",
  "data_origin": "simulation",
  "simulation_run_id": "default_run",
  "source_dataset": "derived_simulation",
  "created_at": "2026-09-25T09:00:00Z",
  "metadata": {
    "days": 90,
    "total_amount": 630.0,
    "rate_per_day": 7.0
  }
}
```

### The 4 Origin Classifications:
* **`SOURCE`**: Immutable data imported verbatim from CSV datasets into `SourceCustomer` and `SourceInteraction`. Never modified.
* **`APPLICATION`**: Operational entities (`User`, `Appliance`) derived and normalized from source records.
* **`SIMULATION`**: Artificial runtime events (`Booking`, `Installation`, `MaintenanceTicket`, `SimulationEvent`) generated by the behavior engine.
* **`MODEL`**: AI inferences (`ChurnScore`, `RecommendationLog`) generated by ML models.

## 4. Simulation Engine & Lifecycle Architecture

### Simulation Clock (`SimulationClock`)
- Decouples execution time from real wall-clock time.
- Advances by arbitrary time slices (`+1 Day`, `+7 Days`, `+30 Days`).
- Deterministic initialization via seed (Default: `20260925`).

### Customer Lifecycle State Machine
```text
[Tenant Session]
       ↓
[Browse Appliances (Empirical Category Weights)]
       ↓
[Recommendation Engine Inferred & Served]
       ↓
[Add to Cart (Demand Multiplier Applied)]
       ↓
[Booking Created (Lease Agreement)]
       ↓
[Payment & Security Deposit Captured]
       ↓
[Technician Dispatched (Installation Completed)]
       ↓
[Active Rental Phase]
       ├── (Maintenance Request Ticket Opened if Probability Met)
       └── (Maturity Check)
                 ├── Renewal (Term Extended, New Total Billed)
                 └── Return (Asset Released to Catalog, Deposit Refund Initiated)
```

### The 4 Configurable Operational Scenarios
1. **Normal Baseline (`normal`)**: Standard empirical conversion, baseline maintenance rate (5%), steady renewal rate (35%).
2. **Cooling Demand Spike (`demand_spike`)**: 2.8x demand surge, 3.5x boost for ACs and 2.2x for Refrigerators, simulating summer heatwaves.
3. **Customer Engagement Decline (`engagement_decline`)**: Inactivity increases by 70%, booking frequency drops by 60%, accelerating churn alerts on the admin panel.
4. **Hardware Failure Wave (`product_failure`)**: Maintenance ticket probability jumps to 35% on active rentals, triggering returns and dissatisfaction events.

## 5. Machine Learning Models Specification

### 1. Recommendation Engine (`ml_recommend`)
- **Algorithms**: User-User Cosine Similarity, Item-Item Cosine Similarity, and Truncated SVD Matrix Factorization (Latent Factors = 12).
- **Explainability**:
  - `match_score`: Derived similarity percentage (e.g. `97.0%`).
  - `recommendation_reason`: Textual justification grounded in model features (e.g. `"Matches your recent rental preferences"`, `"Popular top-rated Laptop among tenants"`).
  - `model_version`: `collaborative_svd_v1`.

### 2. Churn Prediction Model (`ml_churn`)
- **Algorithm**: Random Forest Classifier trained on RFM features.
- **Input Features**:
  - `recency_days`: Inactive days since last booking.
  - `frequency_count`: Total active and completed rental contracts.
  - `monetary_total`: Cumulative amount billed.
- **Output Schema**:
  - `churn_probability`: Continuous probability float (e.g. `0.85`).
  - `risk_level`: `'High'`, `'Medium'`, `'Low'`.
  - `top_features`: Ranked list of feature drivers with impact weights (`'high'`, `'medium'`, `'low'`).
  - `model_version`: `churn_rf_v1`.

## 6. Project Defense Q&A Cheatsheet

If an academic or technical reviewer asks:

> **Q1: "Where did this customer profile come from?"**
> **Answer:** "It was imported from Kaggle's Rental Churn Dataset (`rental_churn_dataset.csv`), record ID `CUST_0013`, and projected into the application layer with provenance record `data_origin: 'source'`."

> **Q2: "Did this rental transaction actually happen in the real world?"**
> **Answer:** "No. This rental was generated deterministically by the RentAI Simulation Engine during run `default_run` at virtual timestamp `2026-10-02`. Its provenance record is tagged `data_origin: 'simulation'`."

> **Q3: "How was this appliance recommendation calculated?"**
> **Answer:** "It was generated by `collaborative_svd_v1` using Truncated SVD Matrix Factorization over 150,000 empirical interaction rows, achieving a similarity match score of 97.0% based on the tenant's category preference vector."

> **Q4: "Why is this tenant flagged as high-risk for churn?"**
> **Answer:** "The Random Forest churn classifier (`churn_rf_v1`) evaluated their RFM vector. The primary risk driver was high inactivity (`recency_days = 38`), combined with late payment history from the source profile."
